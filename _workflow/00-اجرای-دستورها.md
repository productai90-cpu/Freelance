# دستورها را کجا و چطور اجرا کنیم

> اگر با ترمینال راحت نیستید، این فایل را قدم‌به‌قدم دنبال کنید. هیچ چیزی از پیش فرض نگرفته است.

---

## ۱. باز کردن پروژه در VS Code

**File → Open Folder** → پوشهٔ پروژه را انتخاب کنید → **Select Folder**.

⚠️ حتماً **پوشه** را باز کنید، نه یک فایل تنها. اگر فقط فایل باز کنید، ترمینال در جای درستی نخواهد بود.

در نوار کناری چپ باید فهرست فایل‌ها را ببینید: `src`، `public`، `_workflow` و بقیه.

---

## ۲. باز کردن ترمینال

از منوی بالا: **Terminal → New Terminal**

یا کلید میانبر: **``Ctrl + ` ``**
(کلید backtick — سمت چپ عدد ۱، زیر Esc)

پنلی پایین صفحه باز می‌شود با خطی شبیه این:

```
PS C:\Users\hp\Desktop\Project Hall>
```

این خط **می‌گوید الان کجا هستید**. هر دستوری بزنید، در همین پوشه اجرا می‌شود.

اگر مسیر اشتباه بود:

```
cd "C:\Users\hp\Desktop\نام-پوشه"
```

گیومه لازم است چون مسیر فاصله دارد.

---

## ۳. دستور زدن

تایپ کنید، **Enter** بزنید، **صبر کنید تا تمام شود**.

می‌فهمید تمام شده وقتی دوباره خط `PS C:\...>` ظاهر شود. تا وقتی ظاهر نشده، در حال کار است — دستور بعدی را نزنید.

**کپی‌کردن دستور:** با ماوس انتخاب و `Ctrl+C`، بعد در ترمینال **کلیک راست** (در ویندوز کلیک راست یعنی paste).

---

## ۴. ساخت پروژه برای مشتری جدید — کامل

### گام ۱: کپی گرفتن

ترمینال را در پوشه‌ای باز کنید که می‌خواهید پروژه آنجا ساخته شود (مثلاً Desktop):

```
cd "C:\Users\hp\Desktop"
git clone https://github.com/productai90-cpu/Freelance.git نام-مشتری
cd نام-مشتری
```

**چه شد:** پوشه‌ای به اسم `نام-مشتری` ساخته شد با همهٔ فایل‌های قالب.

⏱ چند ثانیه

### گام ۲: قطع اتصال از مخزن قدیمی

```
rm -rf .git
git init
```

**چرا حیاتی است:** `clone` علاوه بر فایل‌ها، **اتصال به مخزن اصلی** را هم می‌آورد. بدون این دو خط، اولین `git push` تغییرات مشتری جدید را **داخل مخزن Freelance شما** می‌ریزد.

⏱ آنی

### گام ۳: نصب ابزارها

```
npm install
```

**چه شد:** پوشهٔ `node_modules` ساخته شد (حدود ۲۰۰ مگابایت). این‌ها کتابخانه‌هایی هستند که هیچ‌وقت داخل گیت نمی‌روند، پس هر بار باید نصب شوند.

⏱ ۱ تا ۳ دقیقه. خطوط زیادی رد می‌شود — طبیعی است.

### گام ۴: پر کردن فایل‌های ورک‌فلو

اینجا **ترمینال لازم نیست**. در نوار کناری VS Code پوشهٔ `_workflow` را باز کنید و فایل‌ها را مثل هر متن دیگری ویرایش کنید. `Ctrl+S` برای ذخیره.

`04-CONTENT.md` و `05-ASSETS.md` را برای مشتری بفرستید تا خودش پر کند.

### گام ۵: ساخت سایت با Claude Code

در VS Code، Claude Code را باز کنید و **کل متن پرامپت داخل `06-BUILD.md`** را بچسبانید.

**این مرحله‌ای است که سایت واقعاً عوض می‌شود.** مراحل قبل فقط زمین را آماده کردند.

⏱ ۱ تا ۲ ساعت

### گام ۶: دیدن نتیجه — سرور محلی

```
npm run dev
```

بعد از چند ثانیه:

```
VITE v8.2.2  ready in 1497 ms
➜  Local:   http://localhost:5173/
```

با **Ctrl + کلیک** روی لینک، مرورگر باز می‌شود.

**نکات مهم سرور محلی:**

| | |
|---|---|
| برای خاموش کردن | داخل ترمینال کلیک کنید، بعد `Ctrl + C` |
| اگر پرسید `Terminate batch job (Y/N)?` | `Y` و Enter |
| تا وقتی روشن است | آن ترمینال مشغول است — برای دستور دیگر ترمینال دوم باز کنید (`Ctrl+Shift+` `) |
| ترمینال را نبندید | با بستنش سایت روی localhost خاموش می‌شود |

**کِی باید restart کنید:**

| تغییر | restart؟ |
|---|---|
| کد `.jsx` یا `.css` | ❌ خودکار |
| `.env.local` | ✅ **بله** |
| `vite.config.js` | ✅ بله |
| `npm install` جدید | ✅ بله |

### گام ۷: بررسی نبود خطا

سرور را با `Ctrl+C` خاموش کنید، بعد:

```
npm run build
```

اگر آخرش نوشت `✓ built in ...` یعنی سالم است. اگر خطا داد، متنش را به Claude Code بدهید.

⏱ چند ثانیه

### گام ۸: انتشار

از `08-LAUNCH.md` ادامه دهید.

---

## ۵. راه ساده‌تر بدون ترمینال (فقط برای گام ۱ و ۲)

اگر `git clone` اذیت کرد:

۱. به https://github.com/productai90-cpu/Freelance بروید
۲. دکمهٔ سبز **Code** → **Download ZIP**
۳. ZIP را در جای دلخواه Extract کنید
۴. پوشه را در VS Code باز کنید

فایل ZIP اصلاً `.git` ندارد، پس گام ۲ لازم نیست. مستقیم از **گام ۳** (`npm install`) شروع کنید.

---

## ۶. خطاهای رایج

| پیام | معنی | راه‌حل |
|---|---|---|
| `npm: command not found` | Node.js نصب نیست | از nodejs.org نسخهٔ LTS را نصب کنید، VS Code را ببندید و باز کنید |
| `git: command not found` | Git نصب نیست | از git-scm.com نصب کنید |
| `Port 5173 is in use` | سرور از قبل روشن است | در ترمینال قبلی `Ctrl+C` بزنید، یا آدرس ۵۱۷۴ را باز کنید |
| `Author identity unknown` | git شما را نمی‌شناسد | `git config user.email "ایمیل"` و `git config user.name "اسم"` |
| `Cannot find module` | `npm install` نزده‌اید | بزنید |
| `ENOENT: no such file` | در پوشهٔ اشتباهی هستید | `cd` به پوشهٔ پروژه |

---

## ۷. اگر `claude` در ترمینال پیدا نشد

روی این سیستم فایل اجرایی Claude Code روی PATH نیست — داخل پوشهٔ افزونهٔ VS Code است. برای دستورهای `claude ...` در PowerShell:

```powershell
$claude = (Get-ChildItem "$env:USERPROFILE\.vscode\extensions\anthropic.claude-code-*-win32-x64\resources\native-binary\claude.exe").FullName
& $claude --version
```

برای کار عادی لازم نیست — از پنل Claude Code داخل VS Code استفاده کنید.

---

## ۸. خلاصهٔ ذهنی

| کار | چه می‌کند |
|---|---|
| `git clone` | اسکلت آماده و تست‌شده را می‌آورد |
| `rm -rf .git` + `git init` | از مخزن قدیمی جدایش می‌کند |
| `npm install` | ابزارها را نصب می‌کند |
| پر کردن `_workflow` | می‌گوید این مشتری چه می‌خواهد |
| **Claude Code** | **اسکلت را به سایت این مشتری تبدیل می‌کند** |
| `npm run dev` | برای دیدن با چشم خودتان |
| `npm run build` | فقط بررسی نبود خطا |
| `git push` | گیت‌هاب خودش build و منتشر می‌کند |

**نکتهٔ کلیدی:** `npm run build` سایت جدید نمی‌سازد. اگر بلافاصله بعد از کلون بزنیدش، دقیقاً سایت تالار مرمر بیرون می‌آید. چیزی که سایت را عوض می‌کند Claude Code است.
