# ۸. انتشار، دامنه، تحویل

## ۱. مخزن

روی گیت‌هاب یک مخزن **خالی** بسازید (بدون README).

```bash
git remote add origin https://github.com/USERNAME/REPO.git
git branch -M main
git add -A
git status          # ← نگاه کنید چه می‌رود
git commit -m "initial"
git push -u origin main
```

⚠️ قبل از commit مطمئن شوید `.gitignore` این‌ها را می‌گیرد: `node_modules`، `dist`، `.env.local`، عکس‌های خام، و هر فایل قیمت یا یادداشت داخلی.

## ۲. Secrets

**Settings → Secrets and variables → Actions → New repository secret**

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | همان URL |
| `VITE_SUPABASE_ANON_KEY` | همان کلید anon |

بدون این‌ها سایت منتشر می‌شود ولی به دیتابیس وصل نیست.

## ۳. فعال کردن انتشار

**Settings → Pages → Source: GitHub Actions**

بعد **تب Actions** (نوار بالای مخزن، نه Settings←Actions) → ورک‌فلو را انتخاب → **Run workflow**.

## ۴. دامنه

### الف) دامنه را به گیت‌هاب وصل کنید

در تنظیمات DNS دامنه:

| نوع | نام | مقدار |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `USERNAME.github.io` |

بعد **Settings → Pages → Custom domain** دامنه را وارد کنید و **Enforce HTTPS** را تیک بزنید.

انتشار DNS تا ۲۴ ساعت طول می‌کشد. معمولاً یکی دو ساعت.

### ب) `vite.config.js` را تنظیم کنید

با دامنهٔ اختصاصی، `base` باید ریشه شود:

```js
base: '/',
```

با زیرمسیر گیت‌هاب (`user.github.io/repo/`) همان `'./'` بماند. **این را یادتان نرود** وگرنه هیچ فایلی لود نمی‌شود.

## ۵. انتقال به مشتری

اگر مشتری می‌خواهد همه‌چیز زیر حساب خودش باشد:

| چه چیزی | چطور |
|---|---|
| مخزن | Settings → General → پایین صفحه → Transfer ownership |
| Supabase | Settings → General → Transfer project (نیاز به سازمان) |
| دامنه | از پنل ثبت‌کننده، انتقال به حساب مشتری |

⚠️ بعد از انتقال مخزن، **Secrets منتقل نمی‌شوند**. مشتری باید دوباره بسازدشان.
